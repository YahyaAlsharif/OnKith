## Assistant integration and the privacy boundary

Six committed clips through the whole system. The boundary counts are read off the bytes handed to `urllib`, not off a function's arguments.

| Device | LLM leg | Payloads | Masked values tested | ...reappearing outbound | Raw transcripts outbound | Detector misses outbound | Cases completed | Run |
|---|---|---:|---:|---:|---:|---:|---:|---|
| Workstation | live | 6 | 9 | **0** | **0** | 2 | 6/6 | `20260823T142736Z_windows-amd64_e2e-v6-whisper_full_workstation` |
| Raspberry Pi 5 | payload audit only | 6 | 9 | **0** | **0** | 2 | 6/6 | `20260823T204627Z_linux-aarch64_e2e-v6-whisper_full` |

`...reappearing outbound` is a boundary failure and must be zero. `Detector misses outbound` is a recall miss by the privacy model, which is why the 44-clip audio benchmark exists; the two must not be added together. A Raspberry Pi row reading `payload audit only` means no API key was configured, so the requests were built and audited but not sent.

## Did adding the assistant change the local core?

No. All 14 quality comparisons between Previous system and Current system, on the same device and the same fixtures, are identical to machine precision.

## Figures

- `model_progression` - Typed entity F1 and character-level error rates for TinyBERT INT8 and DeBERTa INT8 on the same held-out validation split.

- `per_entity_f1` - Typed entity F1 per entity type on the combined validation view, annotated with gold support.
- `ood_model_comparison` - TinyBERT INT8 against DeBERTa INT8 on the OOD development and frozen final fixtures, model-only in both cases.
- `model_size_comparison` - On-disk size of every privacy-model artifact, deployed one highlighted.
- `latency_by_input_length` - Median single-threaded inference latency against input length for all three deployment candidates, on the development workstation.
- `cpu_latency_distribution` - Per-row masking latency distribution and cumulative distribution for the current system on the workstation and on a Raspberry Pi 5.

- `pipeline_latency_breakdown` - Mean latency of each stage inside a masking call and across the assembled pipeline, for the current system on the Raspberry Pi 5. The two audio stages are driven by a synthesised probe tone rather than speech; the real-speech cost is in the audio benchmark section.
  - Runs: `20260823T203840Z_linux-aarch64_v6-whisper_full`
- `cpu_memory_and_throughput` - Peak process RSS, resident privacy-stack cost and masking throughput for the current system on the workstation and on a Raspberry Pi 5.

  - Runs: `20260823T142451Z_windows-amd64_v6-whisper_full_workstation`, `20260823T203840Z_linux-aarch64_v6-whisper_full`
- `audio_pipeline_stage_latency` - Mean per-clip latency of every pipeline stage from audio to post-mask text, and each stage's share of total processing time, for the current system on the Raspberry Pi 5.
  - Runs: `20260823T204339Z_linux-aarch64_audio-v6-whisper_full`
- `audio_duration_scaling` - Audio duration against end-to-end latency, STT latency and STT real-time factor for the current system on the Raspberry Pi 5. RTF below 1 means the device processes speech faster than it arrives; points above the dashed line are clips it did not.

- `audio_latency_by_duration_bucket` - Mean end-to-end latency per clip-duration bucket for the current system on the Raspberry Pi 5, with the observed minimum and maximum as whiskers.
  - Runs: `20260823T204339Z_linux-aarch64_audio-v6-whisper_full`
- `audio_latency_and_memory` - Cumulative distribution of end-to-end latency with P50/P90/P95/P99, and resident memory as each model loads, for the current system on the Raspberry Pi 5, against the 4 GB Raspberry Pi budget.
  - Runs: `20260823T204339Z_linux-aarch64_audio-v6-whisper_full`
- `audio_privacy_reference_vs_pipeline` - Private-character recall and leakage for the same clips scored from written reference text, from uncased unpunctuated reference text, and end to end from audio; plus the attribution of every end-to-end failure. Current system on the Raspberry Pi 5.

  - Runs: `20260818T062503Z_windows-amd64_audio_full_workstation`, `20260818T081310Z_linux-aarch64_audio_full`, `20260820T145659Z_windows-amd64_audio-whisper_full_workstation`, `20260821T201653Z_linux-aarch64_audio-whisper_full`, `20260823T095553Z_windows-amd64_audio-parakeet_full`, `20260823T142306Z_windows-amd64_audio-v6-whisper_full_workstation`, `20260823T204339Z_linux-aarch64_audio-v6-whisper_full`
- `stt_engine_accuracy` - Word error rate and number handling for every measured recognizer on the committed audio benchmark. The raw word error rate is shown in grey to expose how much of it is spelling: Canary wrote numbers as words, Whisper writes numerals, and only the number-normalised bars compare the engines. The right panel separates transcribing a long number correctly from keeping it out of the released text - the two are not the same thing, and the engines differ in opposite directions.
  - Runs: `20260818T062503Z_windows-amd64_audio_full_workstation`, `20260818T081310Z_linux-aarch64_audio_full`, `20260823T095553Z_windows-amd64_audio-parakeet_full`, `20260823T142306Z_windows-amd64_audio-v6-whisper_full_workstation`, `20260823T204339Z_linux-aarch64_audio-v6-whisper_full`

  - Runs: `20260818T062503Z_windows-amd64_audio_full_workstation`, `20260818T081310Z_linux-aarch64_audio_full`, `20260823T095553Z_windows-amd64_audio-parakeet_full`, `20260823T142306Z_windows-amd64_audio-v6-whisper_full_workstation`, `20260823T204339Z_linux-aarch64_audio-v6-whisper_full`

  - Runs: `20260818T062503Z_windows-amd64_audio_full_workstation`, `20260818T081310Z_linux-aarch64_audio_full`, `20260823T095553Z_windows-amd64_audio-parakeet_full`, `20260823T142306Z_windows-amd64_audio-v6-whisper_full_workstation`, `20260823T204339Z_linux-aarch64_audio-v6-whisper_full`

RTF below the dashed line means the device processes speech faster than it arrives; the black rule on each bar is the P90. On the Raspberry Pi the P90 sits above the line, and the clips responsible are the shortest ones - Whisper decodes a fixed window whatever the clip length, so the per-clip cost has a floor.
  - Runs: `20260823T142306Z_windows-amd64_audio-v6-whisper_full_workstation`, `20260823T204339Z_linux-aarch64_audio-v6-whisper_full`
- `current_system_device_quality` - Recognition accuracy, end-to-end privacy after speech recognition, and privacy-model quality on text, for the current system on both devices. Every pair is measured on the same committed fixtures through the same INT8 artifact; the residual differences are INT8 kernel arithmetic on aarch64 against x86-64.

## Tables

- `model_progression.csv` (3 rows) - Model generations with the metric each one actually has on record.
- `deberta_quantization.csv` (5 rows) - FP32 against INT8 on every view, with the deltas the release gate reads.
- `deberta_split_performance.csv` (6 rows) - Every metric of the deployed INT8 model on every evaluation view.
- `per_entity_f1.csv` (30 rows) - Per-entity precision, recall, F1 and support on the combined validation view.
- `ood_model_comparison.csv` (4 rows) - Both deployment models on the OOD development and frozen final fixtures.
- `model_size_comparison.csv` (5 rows) - On-disk size of each privacy-model artifact.
- `latency_by_input_length.csv` (12 rows) - Single-threaded latency at four input lengths on the development workstation.
- `cpu_benchmark_runs.csv` (11 rows) - Every CPU/text benchmark run in the repository, current and historical, with its device, environment and headline numbers. `canonical` marks the run the figures are drawn from.
- `cpu_latency_percentiles.csv` (2 rows) - Latency percentiles of the full masking call, current system, per device.
- `pipeline_latency_breakdown.csv` (20 rows) - Mean latency per stage for the current system on both devices. The figure draws the Raspberry Pi rows.
- `cpu_memory_and_throughput.csv` (2 rows) - Memory footprint and masking throughput of the current system, per device.
- `deployment_parity.csv` (3 rows) - Cross-device agreement and metric deltas for the current system, workstation as reference.
- `audio_deployment_summary.csv` (7 rows) - One row per canonical audio run: 44 clips end to end, with word error rate, real-time factor, latency, memory and end-to-end privacy. The privacy columns are recomputed for every run on the current scoring definition by privacy_eval.rescore, so a folder written before the alignment fix is not compared against one written after it. `aggregate_wer` is each run's own raw figure and is not comparable between recognizers; `aggregate_wer_number_normalised` is.
- `audio_pipeline_stage_latency.csv` (12 rows) - Per-stage mean latency and share of processing time for the current system on both devices. The figure draws the Raspberry Pi rows.
- `audio_clip_scaling.csv` (88 rows) - Per-clip duration, latency and real-time factor for the current system on both devices. The figure draws the Raspberry Pi rows.
- `audio_latency_by_duration_bucket.csv` (8 rows) - End-to-end latency statistics per clip-duration bucket, current system, both devices.
- `audio_memory_breakdown.csv` (12 rows) - Resident memory after each model loads, and the peak during the run, for the current system on both devices.
- `audio_failure_attribution.csv` (8 rows) - Every expected private entity, attributed to protection, a privacy-model failure, or the speech recognizer - current system, both devices.
- `audio_privacy_arms.csv` (3 rows) - Privacy metrics for each route to the model: written reference text, uncased unpunctuated reference text, and the real audio pipeline.
- `audio_word_error_rate.csv` (4 rows) - Word error rate per fixture subset, current system, both devices.
- `audio_postprocessing_amplification.csv` (5 rows) - Spoken numbers the privacy model left unmasked and the display renderer then rewrote into numerals of identifier length, per recognizer generation. Every value is fictional: telephone numbers come from the NANP 555-01xx range reserved for fiction.
- `stt_engine_comparison.csv` (7 rows) - Every measured recognizer arm, scored from its saved transcripts by one implementation. Arms that were never measured on a device are absent rather than zero. `drawn_in_figures` marks the arms the charts show; the previous system's Whisper rows are provenance for the current ones.
- `stt_engine_privacy.csv` (5 rows) - End-to-end privacy per recognizer arm. The entity- and character-level columns are recomputed for every arm by privacy_eval.rescore on one definition - spoken numbers folded on both sides, located regions trimmed to their alphanumeric core - so they are comparable across engines; the released-identifier columns need no alignment at all.
- `current_system_device_cost.csv` (2 rows) - Cost of the current system on each device, with the environment each run recorded for itself.
- `current_system_device_quality.csv` (10 rows) - Every quality metric of the current system measured on both devices, with the difference and the run id behind each side.
- `current_system_inherits_previous_core.csv` (18 rows) - The previous system against the current one on the same device and the same fixtures. Quality metrics are expected to be identical because the local core is unchanged; cost metrics are expected to differ.
- `assistant_privacy_boundary.csv` (2 rows) - The assistant round trip on each device: what reached the outbound request, what the local legs cost, and which live-only measurements exist. Blank or zero live columns on the Raspberry Pi row mean the leg was not attempted because no API key was configured, not that it failed.
