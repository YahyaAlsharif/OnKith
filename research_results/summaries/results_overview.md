## Figures

- `model_progression` - Typed entity F1 and character-level error rates for TinyBERT INT8 and DeBERTa INT8 on the same held-out validation split.
- `deberta_fp32_vs_int8` - FP32 and INT8 typed entity F1 on every evaluation view, with the F1 lost to quantization against the 0.02 release gate.
- `deberta_split_performance` - Typed entity precision/recall/F1 and private-character recall for the deployed INT8 model on each evaluation view.
- `per_entity_f1` - Typed entity F1 per entity type on the combined validation view, annotated with gold support.
- `ood_model_comparison` - TinyBERT INT8 against DeBERTa INT8 on the OOD development and frozen final fixtures, model-only in both cases.
- `model_size_comparison` - On-disk size of every privacy-model artifact, deployed one highlighted.
- `latency_by_input_length` - Median single-threaded inference latency against input length for all three deployment candidates, on the development workstation.
- `cpu_latency_distribution` - Per-row masking latency distribution and cumulative distribution for every benchmarked device.
- `pipeline_latency_breakdown` - Mean latency of each stage inside a masking call and across the assembled pipeline, on the most recent benchmarked device. The two audio stages are driven by a synthesised probe tone rather than speech; the real-speech cost is in the audio benchmark section.
- `cpu_memory_and_throughput` - Peak process RSS, resident privacy-stack cost and masking throughput for every benchmarked device.
- `deployment_parity` - Prediction agreement and typed-F1 difference between benchmarked devices running the identical INT8 artifact.
- `audio_pipeline_stage_latency` - Mean per-clip latency of every pipeline stage from audio to sanitized text, and each stage's share of total processing time.
- `audio_duration_scaling` - Audio duration against end-to-end latency, STT latency and STT real-time factor. RTF below 1 means the device processes speech faster than it arrives.
- `audio_latency_by_duration_bucket` - Mean end-to-end latency per clip-duration bucket, with the observed minimum and maximum as whiskers.
- `audio_latency_and_memory` - Cumulative distribution of end-to-end latency with P50/P90/P95/P99, and resident memory as each model loads, against the 4 GiB Raspberry Pi budget.
- `audio_privacy_reference_vs_pipeline` - Private-character recall and leakage for the same clips scored from written reference text, from uncased unpunctuated reference text, and end to end from audio; plus the attribution of every end-to-end failure.
- `audio_word_error_rate` - Word error rate on the synthetic privacy clips and on the LibriSpeech dev-clean clips, reported separately because they are different distributions.
- `audio_postprocessing_amplification` - The spoken-digit finding: utterances where the privacy model did not mask a spoken number and the display renderer then rendered it as a numeral. Shown for both recognizers, because the V4 count is zero by change of orthography rather than by a change to the renderer.
- `stt_engine_accuracy` - Word error rate and number handling for both recognizers on the committed audio benchmark. The raw word error rate is shown in grey to expose how much of it is spelling: Canary wrote numbers as words, Whisper writes numerals, and only the number-normalised bars compare the engines. The right panel separates transcribing a long number correctly from keeping it out of the released text - the two are not the same thing, and the engines differ in opposite directions.
- `stt_engine_cost` - Real-time factor and end-to-end latency for both recognizers. The dashed line is real time: a bar below it means the device processes speech faster than it arrives. Bars are drawn only for arms that have been measured.
- `stt_engine_released_identifiers` - End-to-end privacy per recognizer. Left: the measure that survives a change of recognizer without any alignment - after masking and after the display renderer, is an identifier-scale number still legible in what the device released? Right: the share of annotated entities that reached no released text, recomputed for all four arms by privacy_eval.rescore so that one scoring definition is applied throughout.

## Tables

- `model_progression.csv` (3 rows) - Model generations with the metric each one actually has on record.
- `deberta_quantization.csv` (5 rows) - FP32 against INT8 on every view, with the deltas the release gate reads.
- `deberta_split_performance.csv` (6 rows) - Every metric of the deployed INT8 model on every evaluation view.
- `per_entity_f1.csv` (30 rows) - Per-entity precision, recall, F1 and support on the combined validation view.
- `ood_model_comparison.csv` (4 rows) - Both deployment models on the OOD development and frozen final fixtures.
- `model_size_comparison.csv` (5 rows) - On-disk size of each privacy-model artifact.
- `latency_by_input_length.csv` (12 rows) - Single-threaded latency at four input lengths on the development workstation.
- `cpu_benchmark_runs.csv` (5 rows) - Every CPU benchmark run discovered, with its device and headline numbers.
- `cpu_latency_percentiles.csv` (4 rows) - Latency percentiles of the full masking call, per device.
- `pipeline_latency_breakdown.csv` (10 rows) - Mean latency per stage for the most recent benchmarked device.
- `deployment_parity.csv` (3 rows) - Cross-device prediction agreement and metric deltas.
- `audio_deployment_summary.csv` (4 rows) - One row per device and recognizer: audio benchmarked end to end, with word error rate, real-time factor, latency, memory and end-to-end privacy. The privacy columns are recomputed for every run on the current scoring definition by privacy_eval.rescore, so a folder written before the alignment fix is not compared against one written after it. The word error rate is each run's own raw figure and is not comparable between recognizers; stt_engine_comparison.csv carries the number-normalised one.
- `audio_pipeline_stage_latency.csv` (6 rows) - Per-stage mean latency and share of processing time for the audio pipeline.
- `audio_clip_scaling.csv` (44 rows) - Per-clip duration, latency and real-time factor behind the scaling figure.
- `audio_latency_by_duration_bucket.csv` (4 rows) - End-to-end latency statistics per clip-duration bucket.
- `audio_memory_breakdown.csv` (6 rows) - Resident memory after each model loads, and the peak during the run.
- `audio_failure_attribution.csv` (4 rows) - Every expected private entity, attributed to protection, a privacy-model failure, or the speech recognizer.
- `audio_privacy_arms.csv` (3 rows) - Privacy metrics for each route to the model: written reference text, uncased unpunctuated reference text, and the real audio pipeline.
- `audio_word_error_rate.csv` (2 rows) - Word error rate per fixture subset.
- `audio_postprocessing_amplification.csv` (4 rows) - Spoken numbers the privacy model left unmasked and the display renderer then rewrote into numerals of identifier length, per recognizer arm. Every value is fictional: telephone numbers come from the NANP 555-01xx range reserved for fiction.
- `stt_engine_comparison.csv` (4 rows) - Every measured recognizer arm, scored from its saved transcripts by one implementation. Rows for arms that have not been measured are absent rather than zero.
- `stt_engine_privacy.csv` (4 rows) - End-to-end privacy per recognizer arm. The entity- and character-level columns are recomputed for every arm by privacy_eval.rescore on one definition - spoken numbers folded on both sides, located regions trimmed to their alphanumeric core - so they are comparable across engines; the released-identifier columns need no alignment at all. pipeline_has_spoken_form_stage says whether the run included the spoken-address rewrite in front of the detectors.
